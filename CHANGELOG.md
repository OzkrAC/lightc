# Changelog

## Unreleased

Changes since 0.1.1. 57 more defects from the November 2026 code review of 0.1.0 are fixed: 8 high, 24 medium and 25 low. 51 are in the library: directory reading, buffered streams, files and sockets, the shared library loader, number and date formatting, sleeps, threads, schedulers, thread-local storage, logging, the dynamic array and the ring buffer, the arena, the io_uring ring, and lightio's loop and coroutine stacks. The others are in the test runner, the socket tests, an example and the docs. The Id column under Fixed is each defect's label in that review. Three API changes are not additive. The `lc_writer` functions that returned nothing now return an `lc_result`, so a write error or a full non-blocking fd is no longer lost unseen. `lc_arena` now has its three counters in every build, so it is 48 bytes whether `NDEBUG` is set or not, where a release build's was 24. `lc_socket_listen_on` takes the address to listen on instead of a port, so a server can listen on loopback alone. Objects compiled against 0.1.1 headers still link, and only those that use `lc_arena` and were built with `NDEBUG` must be recompiled. From now on a program fails to link, instead of running, when its headers and `liblightc.a` are of different minor versions. Otherwise the API only grows, with `lc_kernel_getsockname`, the complete socket wrappers such as `lc_socket_open`, a send and a receive for the io_uring ring, `lc_time_now_ns` and `lc_time_sleep_until`, `lc_kernel_clock_sleep`, `lc_format_length`, six `SYS_*` numbers, `LC_THREAD_MIN_STACK_SIZE`, an `LC_ERR_*` code for every Linux errno, `LC_ERR_UNSUPPORTED` and `FUTEX_PRIVATE_FLAG`, and `api/` now records the public API so that CI catches a change to it. The rest is test and build work: `ninja test` runs every suite with a time limit and ends with a summary, `ninja regress` and `ninja smoke` are new, `./configure ubsan` builds with undefined behaviour checks that trap, and CI runs every build mode with GCC 13 and 14 and the test suites on native aarch64.

### Upgrading: run configure again, check writer results, rebuild arena users, and give lc_socket_listen_on an address

- `lc_socket_listen_on(port, backlog)` is now `lc_socket_listen_on(&addr, backlog)`. For what it did before, listening on every interface, pass the address of `lc_socket_address_any(port)`; `lc_socket_address_create(127, 0, 0, 1, port)` listens on loopback alone. A call that passes a port no longer compiles.
- `lc_socket_create(type)` and `lc_socket_accept(fd, addr)` still work, but are `[[deprecated]]`, so a call warns: use `lc_socket_open(LC_AF_INET, type, 0)` and `lc_socket_accept_flags(fd, addr, &addr_size, 0)`, which take any family and pass every argument the kernel takes.
- Run `./configure` again. ninja does not regenerate `build.ninja`, and one written by 0.1.1 has no `regress` or `smoke` target and runs the suites the old way.
- Recompile what uses `lc_arena` and was compiled with `NDEBUG` against 0.1.1 headers, as most release builds are: there `lc_arena` was 24 bytes, and the library now writes 48. Code built without `NDEBUG` already had the 48-byte layout.
- Each object compiled with the new headers refers to the ABI tag `lc_abi_0_1` of the new `<lightc/version.h>`, which `liblightc.a` defines, so it must be linked with a `liblightc.a` built from these sources: one of 0.1.1, or of another minor version, fails with "undefined reference to `lc_abi_0_1'". Rebuild the library with the headers. A shared object compiled with `-fPIC` has no reference.
- `ninja install` now writes `<lightc/config.h>`, which fixes `LC_STATS` to the library's. Against an install, build without `-DLC_STATS`, or with the library's value: another stops the compile at config.h's `#error`.
- Objects compiled against 0.1.1 headers need not be recompiled, but for the `lc_arena` users above, since the header code they hold behaves the same. The `lc_writer` functions that now return an `lc_result` return it in registers on both arches, so an object compiled against 0.1.1, which ignores it, still links and works. `lc_kernel_fork` passes the same 17, now spelled `SIGCHLD`. `lc_kernel_futex_wait` and `lc_kernel_futex_wake` now pass all six futex arguments, the added ones 0, and the kernel ignores those for `FUTEX_WAIT` and `FUTEX_WAKE`. `lc_error_name` is inline too, so it gives the new names only in code compiled against the new `<lightc/result.h>`; see Behaviour changes.
- `configure` now adds `CFLAGS` and `LDFLAGS` from the environment after its own flags, uses `STRIP` from it for release and tiny links and `OBJCOPY` for tiny ones, and passes `SYSROOT` as `--sysroot`. 0.1.1 ignored all five. Unset them, or set them empty, when they are meant for another project.
- `configure` takes the arch from `$CC -dumpmachine` instead of `uname -m`, and stops when that fails or prints nothing. `ARCH` is still read, and `configure`'s header now calls it deprecated. It must be the arch `CC` targets: `ARCH=aarch64` with an x86_64 `gcc` now stops `configure` with `ARCH=aarch64, but gcc targets ...`, where 0.1.1 went on and failed in ninja.
- Where no io_uring ring can be created, as under qemu-user or with io_uring disabled, `test_async` and `test_lightio` skip every test, and `ninja test` now fails on a suite that skips every test; in 0.1.1 they passed with no test run. On such machines set `LIGHTC_TEST_ALLOW_SKIP="test_async test_lightio"`.
- Code compiled against the new `<lightc/io.h>` that ignores the result of `lc_writer_flush` or `lc_writer_destroy` gets a `-Wunused-result` warning, since both are now `[[nodiscard]]`; check the result, which says whether the bytes were written. Code that stores one of the `lc_writer_*` functions in a pointer to a function returning `void` is rejected by GCC 14 and by clang 16 and newer, and gets a warning from GCC 13. The puts are not `[[nodiscard]]`: a sticky error also comes back from the next flush and from destroy, so on a blocking fd checking those is enough.
- lightc's mutex, condition variable, read-write lock, barrier and once are now private to one process. If you put one in `MAP_SHARED` memory that two processes use, a waiter in one is never woken by the other; use your own futex with the shared flag there.
- On a machine with a `kernel.pid_max` above 32768, such as systemd's default of 4194304, `ninja regress` fails, as the new `HEAP-tid-reuse-tls` skips there. Lower it with `sudo sysctl -w kernel.pid_max=32768` or set `LIGHTC_TEST_ALLOW_SKIP=HEAP-tid-reuse-tls`.
- On aarch64, `ninja regress` needs lld when GNU ld does not pack relative relocations: binutils 2.42, Ubuntu 24.04's, ignores `-z pack-relative-relocs` there, and `LIB-relr` then fails. `configure` uses `ld.lld` from `PATH` for that one test plugin when it has to, and says so.

### Behaviour changes

- **`lc_arena` has one layout.** Its counters `peak_used`, `alloc_count` and `reset_count` are fields in every build, and `LC_STATS` only decides whether they are kept up to date; without it they stay 0. A program built with another `NDEBUG` than the library now agrees with it on the struct.
- **The arena checks its arguments.** `lc_arena_allocate_aligned` aligns the address it returns, so an alignment above the page size is honoured, and it returns NULL for an alignment of 0 or one that is not a power of two, where it used to return memory already handed out or a misaligned pointer. `lc_arena_create` fails, with a NULL `base`, for a size within a page of `SIZE_MAX`.
- **Containers check their arguments.** `lc_array_push` and `lc_array_insert` copy the right value when the element points into the array itself. `lc_ringbuf_create` gives a ring with no buffer, whose pushes fail with `LC_ERR_FULL`, when the capacity or the byte size it needs does not fit in a `size_t`, and `lc_ringbuf_count` never reports more than the capacity.
- **The io_uring ring loses no submission and no completion.** An entry that an `io_uring_enter` did not take, as when it failed with `EAGAIN` or `EBUSY`, stays queued, and each later `lc_async_flush` or `lc_async_wait` offers it again; it used to stay in the ring for ever, and with the queue full the ring wedged. `lc_async_flush` no longer retries such an error: it returns, as the error clears only once completions are reaped. `lc_async_peek` moves completions the kernel held back while the completion queue was full into it, so a loop that only peeks sees them, and every one after them. `lc_async_ring_create` fails with `LC_ERR_OPNOTSUPP` on a kernel without `IORING_FEAT_NODROP`, before 5.5, which drops completions instead; lightc's reads and writes already needed 5.6.
- **`lio_loop_run` returns when io_uring fails.** On an `io_uring_enter` error other than `EINTR`, `EAGAIN` or `EBUSY`, such as `EBADF` after the ring's fd was closed, it returns, and `lio_loop_error` gives the errno; it used to spin at full CPU for ever. A worker of `lio_loop_run_threaded` stops on one alone.
- **Sleeps end on time while signals come.** `lc_time_sleep_milliseconds` and `lc_time_sleep_microseconds` sleep to an absolute `CLOCK_MONOTONIC` deadline with `clock_nanosleep`, so a handled signal that interrupts them delays their end only by the handler's run. They used to start the whole sleep again after each one, and never returned while a signal came more often than the sleep was long. A sleep of 0 or less returns at once.
- **The directory iterator.** A failed `lc_directory_open` leaves the `lc_directory` with no fd and nothing to list, so closing it closes nothing, where it used to close whatever fd the struct held. `lc_directory_close` empties the buffer, so `lc_directory_next` after it returns false. `lc_directory_next` returning false now says why in the new `error` field: 0 at the end, or the errno of a read that failed.
- **Thread creation checks the stack size and leaves no stale handle.** `lc_thread_create_with_stack` fails with `LC_ERR_INVAL` for a `stack_size` below the new `LC_THREAD_MIN_STACK_SIZE` (16 KiB), or one that with the guard page does not fit in a `size_t`, where it used to start a thread that faulted at once and took the process down, and it rounds the stack up to a whole number of pages. A handle whose create failed is all zeros, so `lc_thread_join` of it returns at once. `lio_loop_run_threaded` joins exactly the workers that started, when some did not.
- **The scheduler and lightio take no TLS key.** Each kept its current scheduler or loop in a key of `lc_tls_key_create`, which a program that had taken all 64 shared with them, as key 0. They now keep it in a slot of the per-thread block reserved for the library, so all 64 keys are the program's.
- **lightio's coroutine stacks have a guard page.** A handler that overflows its 64 KiB stack now dies of SIGSEGV where the overflow starts, as a coroutine of `lc_coroutine_create` does, instead of writing on into the memory below. Both set up their stacks with one helper.
- **Headers and library must be of one minor version.** A program whose objects were compiled with lightc's headers fails to link against a `liblightc.a` of another minor version, with "undefined reference to `lc_abi_MAJOR_MINOR'". Patch versions share a tag.
- **`lc_writer` keeps what the fd did not take, and reports errors.** It used to empty its buffer whatever the write returned, so a non-blocking fd, a full disk or a closed pipe lost output and nothing said so. Each put and `lc_writer_flush` now return an `lc_result`: value is the number of bytes accepted, and error is `LC_ERR_AGAIN` when a non-blocking fd would block, with the bytes it did not take kept to flush again, or any other write error. `LC_ERR_AGAIN` is not sticky, but any other error is: it stays in the writer's new `error` field, and every later put, flush and destroy returns it and writes nothing. `lc_writer_destroy` returns its final flush, and drops what that flush could not write, so on a non-blocking fd flush until it succeeds first. A number put can stop partway through its digits on a non-blocking fd. `lc_writer_create(fd, 0)`, and a writer whose buffer allocation failed, write each put at once instead of dropping `put_string`'s bytes.
- **`lc_reader` no longer takes EAGAIN or a read error for the end of the stream.** A read that finds no data on a non-blocking fd returns -1 or a short count with the reader's new `error` field set to `LC_ERR_AGAIN`, and the stream goes on. A read error ends the stream with `error` set to it; at EOF `error` is 0. `lc_reader_read_line` on a non-blocking fd can return part of a line, and the next call the rest. With a `buf_size` of 1 it now returns -1 at the end, and `lc_reader_create(fd, 0)` uses a 4096-byte buffer.
- **Files.** `lc_file_read_all` reads to EOF instead of trusting the size the file reports, so `/proc` and `/sys` files read whole. `lc_file_get_size` uses statx and opens nothing: a FIFO gives 0 at once instead of blocking, a file needs no read permission, a directory gives its size, and a device node gives its `st_size`, usually 0, where the old seek to the end gave a block device's capacity.
- **Sockets.** Every socket lightc opens or accepts is close-on-exec: those of `lc_socket_open`, `lc_socket_create`, `lc_socket_accept`, `lc_socket_accept_flags`, `lc_socket_tcp6`, `lc_socket_udp6`, `lc_socket_accept6`, and the ones lightio accepts. `LC_SOCK_INHERIT`, in the type or the flags, opts out for a socket meant for a program to exec. Every send passes `MSG_NOSIGNAL`, `lc_socket_send_to` too, so a peer that closed gives `LC_ERR_PIPE` instead of killing the process with SIGPIPE. lightio reads and writes with io_uring's receive and send, so a client that resets its connection makes `lio_write` fail with `-EPIPE` where it used to end the server with SIGPIPE; the httpd example sends its responses the same way.
- **`lc_library_open` refuses what it cannot load correctly.** It now applies PLT (`DT_JMPREL`) and packed (`DT_RELR`) relocations, translates every address by the load bias, follows the kernel's page size, and places the library so that each segment keeps its `p_align`, also above the page size. A library that used to load half-relocated now fails: `LC_ERR_UNSUPPORTED` for what a valid library may need and the loader does not do, which is thread-local storage (`PT_TLS`, `DF_STATIC_TLS` or a TLS relocation), IFUNC (an `IRELATIVE` relocation, or one against an IFUNC symbol) and symbol versions (`DT_VERSYM`), and a library with its own copy of lightc, which defines `lc_heap_*`, `lc_tls_*` or `lc_abi_*` symbols; `LC_ERR_RELOC_FAILED` for a relocation against an undefined symbol that is not weak, of a type no psABI gives a shared object (COPY and others), or with a target outside the library; and `LC_ERR_MALFORMED_ELF` for a file shorter than its headers, a `p_align` that is not a power of two, a malformed relocation, symbol or hash table, or two segments with different protections on one page. When the kernel refuses the file, the error is the kernel's errno, such as `EACCES`, `ENOTDIR` or, for a directory, `EISDIR`, where it was `LC_ERR_NOENT` or `LC_ERR_IO`. A weak undefined symbol still resolves to 0. `PT_GNU_RELRO` is read-only once the library is relocated, and the library's file is opened close-on-exec.
- **`lc_library_find_symbol` gives the address a relocation gets.** An absolute symbol's value is returned as it is, where the load bias was added to it, and an IFUNC symbol fails with `LC_ERR_UNSUPPORTED`, where the address of its resolver was returned.
- **Number and date formatting.** `lc_format_add_double_precision` at precision 0 rounds to the nearest integer, a tie to the even one, as printf's `%.0f` does: 0.5 prints 0, 2.5 prints 2, and 0.49999999999999994 prints 0. With pad `'0'`, `lc_format_add_signed_padded` puts the sign first: `-00042`, not `000-42`. The time formatters print a year before 0 with a minus sign: year -1 gives `-0001-12-31T23:59:59Z`.
- **Schedulers.** `lc_scheduler_run` makes the scheduler that was current when it was called current again when it returns, and `lc_scheduler_destroy` clears it, so a yield after a run is the documented no-op.
- **Thread-local storage.** A thread that reuses the id of a thread that has exited starts with every TLS slot NULL.
- **Logging.** There is no log lock. A text line goes out in one writev and a JSON line in one write, so in an `O_APPEND` file, and in a pipe when the line is at most 4096 bytes, lines from other threads and processes never mix into it. Only after a short write does the rest take a second write. A child can log after fork, and threads behind a blocked write sleep instead of spinning. `lc_log_commit` of an entry that `lc_log_begin` filtered writes nothing. A JSON line's `ts` is 0 when the clock cannot be read, and a message that a JSON line cuts short never ends inside a UTF-8 sequence, so the line stays valid UTF-8.
- **`lc_error_name` names every Linux errno.** It returned `"UNKNOWN"` for the 112 errno values that had no `LC_ERR_*` code, such as 9, and now returns their names, such as `"EBADF"`. A value with two names gives the first: `"EAGAIN"` for 11 and `"EDEADLK"` for 35. Every value it named before keeps its name. Check any code that tests its result for `"UNKNOWN"`.

### Fixed

| Id | Severity | What users see |
| --- | --- | --- |
| TIME-sleep-eintr | high | `lc_time_sleep_milliseconds` and `lc_time_sleep_microseconds` started the whole sleep again each time a signal handler interrupted it, so a periodic signal more frequent than the sleep kept it from ever returning. They now sleep to an absolute deadline. |
| LIO-coro-stack-align | high | lightio set up its coroutine stacks apart from `coroutine.c` and got none of its fixes: on x86_64 a handler started with the stack misaligned by 8, so an aligned SSE spill in it faulted, and its stack had no guard page, so an overflow wrote on into the memory below. lightio now uses the same stack helper as `coroutine.c`: the stack is aligned as after a call and has a guard page. |
| IO-writer-drops-data | high | `lc_writer` emptied its buffer whatever a write returned and reported nothing, so a non-blocking fd, a full disk or a closed pipe lost output unseen. It now keeps the bytes the fd did not take and returns the error; see Behaviour changes. |
| LIB-jmprel | high | `lc_library_open` never applied a library's PLT relocations, so the first call through the PLT jumped to an unrelocated address and crashed. It now applies them with the others. |
| LIB-tls | high | A library with thread-local data loaded, and its TLS accesses wrote through the host's thread pointer into lightc's heap block. Such a library now fails to load with `LC_ERR_UNSUPPORTED`. |
| CORO-sched-tls | high | `lc_scheduler_run` never set the current scheduler back, so a yield after a run, or after a helper had destroyed its own scheduler, resumed a finished or freed frame. Each run now restores the scheduler that was current before it, and destroy clears it. |

| async-1 | medium | When an `io_uring_enter` failed with `EAGAIN` or `EBUSY`, the entries it had been offered were never offered again: later operations lagged behind them for ever, and with the submission queue full the ring wedged, its wait never returning. | async-2 | medium | `lc_async_peek` never made the `io_uring_enter` that moves completions the kernel holds back while the completion queue is full, so after one overflow a loop that only peeked saw none of them, nor any later completion. It now makes it. |
| IO-reader-error-eof | medium | `lc_reader` took EAGAIN, and every read error, for the end of the stream, so a non-blocking reader stopped for good at the first empty read. It now sets `error` and goes on after EAGAIN. |

| LIB-pagesize | medium | The loader aligned segments to 4 KiB pages, so on an aarch64 kernel with 16 or 64 KiB pages libraries failed to load. It now uses the kernel's page size, and refuses a library whose segments with different protections share one of its pages. |
| LIB-unresolved-ok | medium | A relocation against an undefined symbol that is not weak, or of a type the loader does not apply, was skipped, and `lc_library_open` reported success. It now fails with `LC_ERR_RELOC_FAILED`, or with `LC_ERR_UNSUPPORTED` for a TLS or IFUNC relocation. |

The example now declares the entry and passes `&entry`, and a note says not to copy the entry between begin and commit. |

### Added

- `lc_kernel_getsockname(fd, addr, addr_length)` in `<lightc/syscall.h>`. It copies a socket's local address, so after a bind to port 0 it gives the port the kernel picked.
- `SYS_getsockname` (51 on x86_64, 204 on aarch64), `SYS_setitimer` (38 on x86_64, 103 on aarch64), `SYS_prlimit64` (302 on x86_64, 261 on aarch64), `SYS_getsockopt` (55 on x86_64, 209 on aarch64), `SYS_fcntl` (72 on x86_64, 25 on aarch64) and `SYS_clock_nanosleep` (230 on x86_64, 115 on aarch64) in `<lightc/arch/*/syscall_nr.h>`. Remove any copies you defined yourself.
- An `LC_ERR_*` code in `<lightc/result.h>` for every errno of Linux's `asm-generic/errno-base.h` and `asm-generic/errno.h`, with the kernel's name and value: 114 new names, such as `LC_ERR_BADF` (9), `LC_ERR_FAULT` (14) and `LC_ERR_BUSY` (16). As in the kernel, `LC_ERR_WOULDBLOCK` is `LC_ERR_AGAIN` and `LC_ERR_DEADLOCK` is `LC_ERR_DEADLK`. Remove any of these you defined yourself: an enumerator declared twice does not compile.
- Nothing in the public headers was removed or renamed, and no value changed on either arch: the 19 errno codes of 0.1.1 and the library codes from 4096 keep their names and values, and every `SYS_*` number is the same. The `SYS_*` lines are now generated, in number order, each with a comment giving the syscall's argument count.
- `LC_ERR_UNSUPPORTED` (4104) in `<lightc/result.h>`, which `lc_error_name` names `"UNSUPPORTED"`: a valid library that needs what `lc_library_open` does not do, or that has its own copy of lightc, and an IFUNC or TLS symbol that `lc_library_find_symbol` has no address for.
- In `<lightc/socket.h>`, wrappers that pass every argument the kernel takes: `lc_socket_open(family, type, protocol)` opens a socket of any family, a netlink one among them; `lc_socket_accept_flags(fd, addr, addr_size, flags)` passes accept4's flags; `lc_socket_get_option` and `lc_socket_set_option` take a level, a name, a buffer and its length; `lc_socket_send_to_sockaddr` and `lc_socket_receive_from_sockaddr` take an address of any family and its length, and flags. With them `LC_AF_UNIX`, `LC_AF_NETLINK`, `LC_SOCK_RAW`, `LC_SOCK_NONBLOCK`, `LC_SO_ERROR` and lightc's own `LC_SOCK_INHERIT`.

- `lc_format_length(fmt)` in `<lightc/format.h>`: the length of the text the buffer holds, the one to write or print. `lc_format_finish` still returns the length the whole text would have, as snprintf does, which is more after an overflow.

- `FUTEX_PRIVATE_FLAG` (128) in `<lightc/syscall.h>`, next to `FUTEX_WAIT` and `FUTEX_WAKE`.

Release and tiny builds strip that section.

An error that `lc_async_flush`, `lc_async_wait` or `lc_async_peek` cannot report is kept in the ring, and the next `_ex` call reports it. A signal ends `lc_async_wait_ex`'s wait with no error, where `lc_async_wait` waits again.

Each fills padding the struct already had, so neither changes size or moves a field. `lc_directory` gains one too: the errno of a failed open, or of the read that ended a listing early, such as EBADF for a fd closed underneath it, and 0 when `lc_directory_next` returns false at the end. ### Notes for lightbox

- lightbox needs no change. Its sources compile against the new headers for both arches with no new warning. It calls none of the changed stream, file, socket, loader, log, io_uring or lightio functions, uses none of lightc's sync objects, threads or `lc_time` formatters, formats no doubles or padded signed numbers, and maps no `MAP_SHARED` memory, so its output and behaviour cannot change.

CI's aarch64 cross job runs lightbox's `ARCH`, `CC` and `AR` line for aarch64. Once its lightc is past 0.1.1, lightbox can drop `ARCH=` from that line, since `configure` takes the arch from `CC`.

## 0.1.1

A hotfix for 0.1.0. A fresh clone builds again, and 11 defects found in a November 2026 code review of 0.1.0 are fixed: 8 high, 2 medium and 1 low. The Id column under Fixed is each defect's label in that review. CI again builds and tests every push and pull request to main or master, and now also runs the test suites on aarch64 under qemu-user.

### Upgrading: rebuild, do not just relink

- Several fixes are in header code that gets compiled into your own objects. In `<lightc/syscall.h>` these are the `static inline` `lc_kernel_mount`, `lc_kernel_fchmodat` and `lc_kernel_reset_signal`, the `lc_kernel_sigaction` struct (32 bytes on aarch64, 24 before) and the `O_*` macros. The `SYS_*` numbers are in `<lightc/arch/*/syscall_nr.h>`, which it includes. An object compiled against 0.1.0 headers keeps the old code, so recompile every file that includes a lightc header.
- Rebuild lightc itself from a fresh `./configure`. ninja does not regenerate `build.ninja`, and a 0.1.0 `build.ninja` does not parse.
- Link against the new `liblightc.a` and the new linker scripts. An old `liblightc.a` still ends `main` with `SYS_exit`. 0.1.0 did not install the linker scripts, so replace any copy kept in your own tree: an old script keeps the aarch64 page bug, emits no `PT_GNU_STACK` and runs no link checks.
- With pkg-config, `--libs` now gives `-static -nostdlib -nostartfiles` and `-T` with `lightc.ld`. Drop any of these you added for 0.1.0. A second `-T` is added to the first, not used in its place, and doubles the program headers. Put the `--libs` flags after your sources, since `-llightc` is a static archive.
- `configure` now reads `ARCH` from the environment. A value other than `x86_64` or `aarch64`, such as the kernel's `arm64`, stops it with `Unsupported architecture`, so unset `ARCH` if something else sets it.

### Behaviour changes

- **`lc_kernel_mount` mounts on x86_64.** In 0.1.0 it ran sendfile, so nothing was mounted. Calls that did nothing before now mount, so check that each caller still means it and handles the result.
- **`lc_kernel_fchmodat` with flags needs Linux 6.6.** Non-zero flags go to fchmodat2. Before Linux 6.6 that call fails, and the wrapper returns `-EOPNOTSUPP`. It never falls back to fchmodat, which would drop the flags. `AT_SYMLINK_NOFOLLOW` on a symlink returns `-EOPNOTSUPP` on every kernel, since Linux has no symlink modes. Flags 0 behave as before. `docs/guide.html` describes the `O_PATH` fallback for refusing symlinks on older kernels.
- **`thread_local`, constructors and destructors fail to link.** lightc has no TLS segment, and its start code never runs the program's `.preinit_array`, `.init_array` or `.fini_array`, so such code used to link and then misbehave. Libraries opened with `lc_library_open` still get their constructors and destructors run. Links that use `lightc.ld` or `lightc-tiny.ld` now stop with a `lightc:` message; links with other scripts get no check. pkg-config's `--libs` uses `lightc.ld`. Use the `lc_tls_*` keys instead of `thread_local`, and call setup code from `main`.
- **Returning from `main` ends every thread.** `_start` now calls exit_group, not exit. A program whose threads are still running when `main` returns exits at once with `main`'s value, and those threads stop wherever they are. In 0.1.0 the process kept running until its last thread ended. Join any thread whose work must finish before you return from `main`. A plain return still runs no atexit handlers.

- `O_NOFOLLOW` and `O_DIRECT` with per-arch values, and `AT_SYMLINK_NOFOLLOW` (0x100), in `<lightc/syscall.h>`. Remove any copies you defined yourself.
- `SYS_fchmodat2` (452 on both arches) in `<lightc/arch/*/syscall_nr.h>`.
- `LC_ERR_NOSYS` (38) and `LC_ERR_OPNOTSUPP` (95) in `<lightc/result.h>`, with their names in `lc_error_name`.
- `ninja install` puts `lightc.ld` and `lightc-tiny.ld` in `<prefix>/lib/lightc/`. `lightc.pc` passes `-T` with the first and names the second in its `ldscript_tiny` variable; `docs/index.html` shows how to link with it. On aarch64 the installed Cflags add `-mno-outline-atomics`, which builds that skip pkg-config must pass themselves.
- `configure` takes the target arch from `ARCH`. `ARCH=aarch64 CC=aarch64-linux-gnu-gcc AR=aarch64-linux-gnu-ar ./configure debug` sets up a cross build; see Build and CI for the targets to build on aarch64.

### Build and CI

- A fresh clone builds: ninja no longer stops at `build.ninja:237` with a lexing error. On aarch64 a plain `ninja` still stops in `examples/bench_heap.c`, which uses the x86-only `rdtsc`. There, run `ninja build/liblightc.a` for the library, or `ninja test` to build and run the test suites. A cross build can build the suites without running them with `ninja tests build/test_plugin.so`.
- aarch64 builds pass `-mno-outline-atomics`, so they no longer need libgcc's atomic helpers.
- `ninja test` builds the plugin `test_library` loads, runs all 19 suites, including `test_lightio` and the new `test_syscall`, and shows each suite's output as it runs.
- The Build & Test workflow is back. It has debug, release and tiny jobs, a kernel ABI check for both arches, a pkg-config consumer check, and the test suites on aarch64 under qemu-user.
- Binaries are smaller: x86_64 tiny hello drops from 8200 B to 4448 B, because `.data` no longer starts on a fresh page in the file.

### Notes for lightbox

- Rebuild lightbox and its lightc as described above. lightbox's Makefile builds `lightc/build/liblightc.a` only when it is missing, and `make clean` leaves it, so delete it after moving the submodule to 0.1.1. With `LIGHTC=` pointing at another tree, run `make clean` after switching trees, because lightbox does not recompile when only that tree changes.
- On x86_64, lightbox at `9dfe420` or older calls `lc_kernel_mount` without checks during `setup`. Rebuilt against 0.1.1, it really mounts cgroup2 on `cgroup_root`; under 0.1.0 that call ran sendfile. Use lightbox `5179e04` or later, which checks the cgroup root first.
- lightbox from its `ls` rewrite on passes `AT_SYMLINK_NOFOLLOW` to its own statx. lightc defines that constant only from 0.1.1, so that lightbox no longer builds against 0.1.0 headers.
- On aarch64, lightbox's volume-source check and its container listing now open with a real `O_DIRECTORY`. 0.1.0 passed `O_DIRECT` there, so a regular file given as a volume source could pass the directory check; with 0.1.1 it fails it.
- The lightbox binary now has a `GNU_STACK` RW header, so its stack is not executable.
- lightbox's private `LB_SYS_mount` can go once it is pinned to 0.1.1, since `lc_kernel_mount` uses 165 on x86_64.
- lightbox needs no source change for the fchmodat, link-check or exit_group changes. It passes flags 0 to fchmodat, uses no `thread_local`, constructors or destructors, and starts no threads.
