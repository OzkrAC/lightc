A fallible call returns a small struct carrying both the outcome and an error code; the caller inspects the code. Two shapes are used throughout the API. :::member{#lc_result} ```c typedef struct { int64_t value; int32_t error; } lc_result; ``` Result of a call that yields an integer or nothing. `error` is `LC_OK` (0) on success, else an `LC_ERR_*` code; `value` is meaningful only when `error == LC_OK`. ::: :::member{#lc_result_ptr} ```c typedef struct { void *value; int32_t error; } lc_result_ptr; ``` Result of a call that yields a pointer. On success `value` is the pointer and `error` is `LC_OK`; on failure `value` is `NULL` and `error` is an `LC_ERR_*` code. ::: **Constructors and predicates.** All are `static inline` in `result.h`. | Function | Meaning | |---|---| | `lc_ok(int64_t v)` → `lc_result` | success carrying `v` | | `lc_err(int32_t e)` → `lc_result` | failure with code `e` | | `lc_ok_ptr(void *p)` / `lc_err_ptr(int32_t e)` → `lc_result_ptr` | pointer success / failure | | `lc_is_ok(r)` / `lc_is_err(r)` → `bool` | test an `lc_result` | | `lc_ptr_is_ok(r)` / `lc_ptr_is_err(r)` → `bool` | test an `lc_result_ptr` | | `lc_error_name(int32_t e)` → `const char *` | human-readable code name, e.g. `"ENOMEM"` | | `lc_result_from_sysret(int64_t)` → `lc_result` | fold a raw `lc_sysret` into an `lc_result` | ```c lc_result_ptr r = lc_heap_allocate(256); if (lc_ptr_is_err(r)) return 1; // r.error holds the LC_ERR_* code uint8_t *buf = r.value; // valid only on the ok path ``` **Error codes.** `error` is `0` for success or a positive `LC_ERR_*` constant otherwise. `result.h` has an `LC_ERR_*` constant for every Linux errno, named after it and with its value: `LC_ERR_BADF` is `EBADF` (9), `LC_ERR_OPNOTSUPP` is `EOPNOTSUPP` (95). `lc_error_name` returns the errno's name, such as `"EBADF"`. lightc's own codes start at 4096. | Code | Meaning | |---|---| | `LC_OK` | success (0) | | `LC_ERR_NOMEM` | allocation failed | | `LC_ERR_INVAL` | invalid argument | | `LC_ERR_NOENT` | no such file or object | | `LC_ERR_AGAIN` | temporarily unavailable (e.g. queue full) | | `LC_ERR_IO` | I/O error | :::note Allocating functions are `[[nodiscard]]`: the compiler warns if the result is dropped. One level below the typed API, raw syscalls return `lc_sysret` (an `int64_t`): non-negative on success, or `-errno` on failure — the raw Linux convention. `lc_result_from_sysret` maps the `[-4095,-1]` range to an error. ::: ## Program lifecycle {#lifecycle} ### Startup {#startup} The kernel loads the static ELF and enters `_start` (hand-written assembly, `arch//start.S`) with `argc`, `argv`, `envp` and the auxiliary vector on the stack. Before `main`, `_start`: 1. clears the frame pointer for a clean backtrace base; 2. on x86_64, points the thread pointer at a heap TLS sentinel so the first `%fs:0` read in the allocator cannot fault; 3. calls `lc_runtime_init(stack_top)`, which scans the auxiliary vector for `AT_PAGESZ` and records the kernel's real page size; 4. reads `argc`, `argv`, `envp` and calls `main(argc, argv, envp)`; 5. passes `main`'s return value to the `exit_group` syscall. There is no C runtime, so nothing runs the program's own constructors or destructors and there is no static TLS (a library loaded with `lc_library_open` does get its `DT_INIT` and `.init_array` run, and `lc_library_close` runs its `.fini_array` and `DT_FINI`, but one with thread-local storage fails to load, with `LC_ERR_UNSUPPORTED`, as does one linked with its own `liblightc.a`). A program that uses `thread_local`, or defines a function with `__attribute__((constructor))` or `__attribute__((destructor))`, fails to link with a `lightc:` message from the linker script (`lightc.ld` or `lightc-tiny.ld`; the pkg-config flags pass `lightc.ld`). Keep per-thread data in the [`lc_tls_*` keys](threads.html#tls) and call setup code from `main`. `main`'s signature is `int main(int argc, char **argv, char **envp)` because there is no global `environ`. ### Exit {#exit} Returning from `main` calls `exit_group` directly — no handlers run. To run cleanup, use `lifecycle.h`. :::member{#lc_atexit} ```c [[nodiscard]] lc_result lc_atexit(lc_atexit_func func); ``` Register `func` (a `void (*)(void)`) to run at `lc_exit`. Up to `LC_MAX_ATEXIT_HANDLERS` (32) may be registered. Returns `LC_ERR_FULL` when the table is full. ::: :::member{#lc_exit} ```c void lc_exit(int code) __attribute__((noreturn)); ``` Run the registered handlers in last-in-first-out order, then `exit_group(code)`. The handler chain runs **exactly once**: re-entry — a signal arriving mid-shutdown, or a handler that itself calls `lc_exit` — is guarded and does not re-run it. A plain `return` from `main` does **not** run atexit handlers. ::: ## The syscall layer {#syscalls} `syscall.h` is the single point of contact with the kernel: seven argument-count trampolines, a wide set of named wrappers over them, and the constants they take. Syscall numbers differ per architecture (`arch//syscall_nr.h`); the wrappers hide that. | Trampoline | Form | |---|---| | `lc_syscall0(nr)` … `lc_syscall6(nr, a0…a5)` | raw syscall, returns `lc_sysret` (`-errno` on error) | Named wrappers follow the pattern `lc_kernel_*`: `lc_kernel_read_bytes`, `lc_kernel_write_bytes`, `lc_kernel_open_file`, `lc_kernel_close_file`, `lc_kernel_map_memory`, `lc_kernel_unmap_memory`, `lc_kernel_seek_position`, and many more. Two groups warrant explicit documentation, as does `lc_kernel_fchmodat`. :::member{#lc_kernel_map_memory} ```c void *lc_kernel_map_memory(void *addr, size_t len, int32_t prot, int32_t flags, int32_t fd, int64_t offset); ``` `mmap` wrapper. Returns the mapping, or `MAP_FAILED` (`(void *)-1`) on failure — the raw `-errno` the kernel returns is normalized to `MAP_FAILED`. Test the result against `MAP_FAILED`, not for a small negative pointer. ::: :::member{#lc_kernel_write_all} ```c lc_sysret lc_kernel_write_all(int32_t fd, const void *buf, size_t count); lc_sysret lc_kernel_read_all (int32_t fd, void *buf, size_t count); lc_sysret lc_kernel_read_retry(int32_t fd, void *buf, size_t count); ``` EINTR- and partial-transfer-safe I/O. `write_all` writes the whole buffer, retrying on `EINTR` and looping over short writes; `read_all` reads until the buffer is full or EOF; `read_retry` performs one read, retrying only `EINTR`. Each returns the byte count, or a negative errno. Prefer these over bare `lc_kernel_read_bytes`/`write_bytes` for buffered and whole-object I/O so a signal never silently drops data. ::: :::member{#lc_kernel_fchmodat} ```c lc_sysret lc_kernel_fchmodat(int32_t dirfd, const char *path, int32_t mode, int32_t flags); ``` Change the mode of `path`, relative to `dirfd` (`AT_FDCWD` for the working directory). With `flags` 0 this is `fchmodat`, which follows a symlink to its target. The kernel's `fchmodat` takes no flags, so non-zero `flags` such as `AT_SYMLINK_NOFOLLOW` go to `fchmodat2`, which needs **Linux 6.6**. Older kernels report `-ENOSYS` for it, returned as `-EOPNOTSUPP` (`-LC_ERR_OPNOTSUPP`). The call never falls back to `fchmodat`, which would drop the flags and change the mode of the link's target. Linux has no symlink modes, so `AT_SYMLINK_NOFOLLOW` on a symlink returns `-EOPNOTSUPP` on every kernel. To refuse symlinks on kernels before 6.6, use glibc's `O_PATH` fallback: open `path` with `O_PATH | O_NOFOLLOW | O_CLOEXEC`, `fstat` the descriptor and stop with `-EOPNOTSUPP` if it is a symlink, otherwise call `lc_kernel_fchmodat(AT_FDCWD, "/proc/self/fd/", mode, 0)` and close it. This needs `/proc` mounted. `syscall.h` defines neither `O_PATH` (`010000000`) nor an `fstat` wrapper. ::: **Constants.** `syscall.h` also defines the flags and file descriptors the wrappers take: `STDIN` (0), `STDOUT` (1), `STDERR` (2); open flags `O_RDONLY`, `O_WRONLY`, `O_CREAT`, `O_TRUNC`; protection `PROT_READ`, `PROT_WRITE`, `PROT_EXEC`; mapping `MAP_PRIVATE`, `MAP_SHARED`, `MAP_ANONYMOUS`, `MAP_FIXED`. :::member{#lc_runtime_page_size} ```c size_t lc_runtime_page_size(void); ``` The kernel's real page size, captured from `AT_PAGESZ` at startup (`memory.h`). `LC_PAGE_SIZE` (4096) is the compile-time allocation-granularity assumption; this is the actual page size, which on aarch64 may be 16 KiB or 64 KiB. Guard pages are sized from this value. ::: ## Types and strings {#types} `types.h` takes the fixed-width integer types (`uint8_t`, `int32_t`, `uint64_t`, …), `size_t` and `NULL` from `` and ``, which with `-ffreestanding` are the compiler's own headers, not libc's. It includes `version.h`, which gives the version (`LC_VERSION_*` and `lc_version()`) and the ABI tag: each object compiled with these headers refers to `lc_abi_MAJOR_MINOR`, so a program fails to link against a `liblightc.a` of another minor version. `bool`, `true` and `false` are C23 keywords, and `result.h`, which `types.h` includes, also includes ``. `lc_sysret` is an `int64_t`. `string.h` provides string and byte operations that lower to the compiler's `__builtin_*` routines; lengths are explicit, so no API assumes NUL termination. | Function | Operation | |---|---| | `lc_string_length(s)` | length to the NUL terminator | | `lc_string_equal(a, alen, b, blen)` | compare two sized strings | | `lc_bytes_copy(dst, src, n)` | copy `n` bytes | | `lc_bytes_fill(dst, byte, n)` | fill `n` bytes | | `lc_bytes_compare(a, b, n)` | compare `n` bytes | {.source} Headers: `include/lightc/result.h`, `lifecycle.h`, `syscall.h`, `types.h`, `version.h`, `string.h`. Source: `src/lifecycle.c`, `src/memory.c`, `arch//start.S`, `arch//syscall.S`. ## Math {#math} `` is libc's, so lightc has `math.h`, which declares only `lc_` names. `` is the compiler's, and still gives `FLT_MAX`, `FLT_EPSILON` and the rest. lightc has no libm, and nothing in `math.h` needs one. `lc_isnan(x)`, `lc_isinf(x)`, `lc_isfinite(x)` and `lc_signbit(x)` classify a float or a double as ``'s macros of those names do, and give a `bool`. Each is a type-generic macro that calls the function for the type of `x`, such as `lc_float_isnan` or `lc_double_isnan`, so `x` is evaluated once and not converted; any other type does not compile. They test the bits of `x`, which `lc_float_to_bits` and `lc_double_to_bits` give, so GCC's flags do not change their answers: under `-ffast-math`, GCC folds `__builtin_isnan(x)` to false, and `__builtin_signbit(x)` to `x < 0`, which is false for `-0`, while these still give the class of `x`. That is checked with GCC, not with clang. What they classify is the value the compiled code made, though, and `-ffast-math` lets the compiler rewrite arithmetic, so an expression that gives a NaN, an infinity or `-0` under IEEE 754 can give another value there. | Constant | Value | |---|---| | `LC_INFINITY`, `LC_NAN` | positive infinity and a quiet NaN, as floats, which convert to doubles exactly | | `LC_PI`, `LC_PI_F` | π, as a double and as a float | | `LC_E`, `LC_E_F` | e | | `LC_LN2`, `LC_LN2_F` | ln 2 | Each constant is correctly rounded to its type: the float forms are literals of their own, not the doubles rounded again. ### Exact functions {#math-exact} `lc_sqrtf`, `lc_floorf` and the other functions of the table are ``'s functions of those names without `lc_`. Each is exact: it gives the correctly rounded result, bit for bit, with C23 Annex F's special values, and the same bits on x86_64 and aarch64. No `errno` is set and no FP flag is read, and the rounding mode is always to nearest, ties to even, as lightc never changes it. A NaN in gives a quiet NaN out, of no particular sign or payload, but `lc_fabsf` and `lc_copysignf` change only the sign bit, of a NaN too. | Function | Result | |---|---| | `lc_sqrtf(x)`, `lc_sqrt(x)` | the square root | | `lc_floorf(x)`, `lc_ceilf(x)`, `lc_truncf(x)`, and `lc_floor`, `lc_ceil`, `lc_trunc` | `x` rounded down, up, or toward zero, to an integer | | `lc_roundf(x)`, `lc_round(x)` | the nearest integer, ties away from zero | | `lc_rintf(x)`, `lc_nearbyintf(x)`, `lc_rint(x)`, `lc_nearbyint(x)` | the nearest integer, ties to even | | `lc_lrintf(x)` | the nearest `long`, ties to even, saturated | | `lc_fmaf(x, y, z)`, `lc_fma(x, y, z)` | `x * y + z`, rounded once | | `lc_fminf(x, y)`, `lc_fmaxf(x, y)`, `lc_fmin`, `lc_fmax` | the smaller or the larger; a NaN and a number give the number | | `lc_fabsf(x)`, `lc_copysignf(x, y)` | `x` with its sign bit clear, or with the sign bit of `y` | | `lc_frexpf(x, &e)` | a fraction of magnitude in [0.5, 1), and in `e` the power of 2 that makes `x` | | `lc_ldexpf(x, n)`, `lc_scalbnf(x, n)` | `x` times 2 to the power `n`, rounded once | Where C leaves the result open, lightc gives the same on both arches: `lc_rintf` and `lc_nearbyintf` are one function; `lc_fminf` of `-0` and `+0`, in either order, is `-0`, and `lc_fmaxf` of them `+0`, and a signalling NaN gives a quiet NaN, as aarch64's `fminnm` and `fmaxnm` do; `lc_lrintf` gives 0 for a NaN, `LONG_MAX` from 2^63 up and `LONG_MIN` below -2^63; `lc_frexpf` stores 0 for ±0, an infinity and a NaN. Each is `static inline` over the GCC builtin of its name, such as `__builtin_floorf`, so it is one instruction where the target has one, also in a function with a `target("...")` attribute: `sqrtss`, `roundss` with SSE4.1 and `vfmadd` with FMA on x86_64; `fsqrt`, the `frint` instructions, `fmadd`, `fminnm` and `fmaxnm` on aarch64. Elsewhere GCC calls the function of the standard name, such as `floorf`, which `liblightc.a` defines, as it defines `memcpy`, and which no lightc header declares: a program calls the `lc_` names. Baseline x86_64 has no rounding instruction, so there the rounding functions work on the bits, and `fma` multiplies in integers. `lightc.pc`'s Cflags give `-fno-math-errno`, without which GCC adds a call to `sqrtf` for a negative argument of `lc_sqrtf`. Under `-ffast-math`, GCC may rewrite these functions as it rewrites the program's own arithmetic, and when it folds a call on constants it takes a signalling NaN for a quiet one. Every source of lightc is built with `-fno-math-errno`, and with `-ffp-contract=off`, so that GCC fuses no multiply and add on aarch64 that it keeps apart on x86_64. `tools/math-sweep.c` compares each function with the host's libm: a float function of one argument over all 2^32 floats, and the others on every float with lists of second arguments, or on random samples. `ninja math-sweep` builds it as `build/math-sweep`; it links libc and libm, so neither `ninja` nor `ninja test` builds it. `tests/test_math_exact.c` checks both forms of each function, the `lc_` one and the standard name, on the hard cases in `tests/data/math_exact_cases.h`, which the tool writes. {.source} Header `include/lightc/math.h`, whose functions are each `static inline`; the standard names in `src/math_exact.c`. `tests/test_math.c` is built twice, as `test_math` and, with `-O3 -ffast-math`, as `test_math_fast`; `tests/test_math_builtins.c` four times, at `-O0` and `-O2`, with and without `-fno-math-errno`.
