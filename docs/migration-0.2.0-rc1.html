The sections after them give what changed with no change to the API. `CHANGELOG.md` gives every fix. ::toc ## In short {#short} 1. **Build the program and the library from one version.** Code compiled with the 0.2.0 headers fails to link with a 0.1.1 `liblightc.a`, such as a `build/liblightc.a` left from before: delete it and build again. See [the ABI tag](#abi-tag). 2. **Run `./configure` again.** A `build.ninja` from 0.1.1 has none of the new targets. See [Building and testing](#build). 3. **Give `lc_socket_listen_on` an address**, not a port. See [below](#listen-on). 4. **Check what `lc_writer_flush` and `lc_writer_destroy` return.** See [below](#writer). 5. **Replace `lc_socket_create` and `lc_socket_accept`**, which now warn. See [below](#deprecated). 6. **Recompile what uses `lc_arena` and was built with `NDEBUG`.** See [Struct layouts](#layouts). 7. **Run on Linux 5.10 or later.** See [Kernel](#kernel). 8. **Keep no lightc lock in memory that two processes share.** See [Behaviour changes](#behaviour). ## Changes that need a code change {#breaking} ### lc_writer returns what it did {#writer} | 0.1.1 | 0.2.0-rc1 | |---|---| | `void lc_writer_flush(lc_writer *writer);` | `[[nodiscard]] lc_result lc_writer_flush(lc_writer *writer);` | | `void lc_writer_destroy(lc_writer *writer);` | `[[nodiscard]] lc_result lc_writer_destroy(lc_writer *writer);` | | `void lc_writer_put_byte(lc_writer *writer, uint8_t byte);` | `lc_result lc_writer_put_byte(lc_writer *writer, uint8_t byte);` | | `void lc_writer_put_char(lc_writer *writer, char c);` | `lc_result lc_writer_put_char(lc_writer *writer, char c);` | | `void lc_writer_put_hex(lc_writer *writer, uint64_t value);` | `lc_result lc_writer_put_hex(lc_writer *writer, uint64_t value);` | | `void lc_writer_put_line(lc_writer *writer, const char *str, size_t length);` | `lc_result lc_writer_put_line(lc_writer *writer, const char *str, size_t length);` | | `void lc_writer_put_newline(lc_writer *writer);` | `lc_result lc_writer_put_newline(lc_writer *writer);` | | `void lc_writer_put_signed(lc_writer *writer, int64_t value);` | `lc_result lc_writer_put_signed(lc_writer *writer, int64_t value);` | | `void lc_writer_put_string(lc_writer *writer, const char *str, size_t length);` | `lc_result lc_writer_put_string(lc_writer *writer, const char *str, size_t length);` | | `void lc_writer_put_unsigned(lc_writer *writer, uint64_t value);` | `lc_result lc_writer_put_unsigned(lc_writer *writer, uint64_t value);` | The writer used to empty its buffer whatever the write returned, so a full disk, a closed pipe or a non-blocking fd lost output unseen. Each call now returns an `lc_result` whose `value` is the number of bytes it accepted. Its `error` is `LC_ERR_AGAIN` when a non-blocking fd would block, with the bytes the fd did not take kept for the next flush, or the write's errno, which is sticky: it stays in the writer's new `error` field, and every later call returns it and writes nothing. On a blocking fd, check the last flush or the destroy: ```c lc_writer out = lc_writer_create(fd, 4096); lc_writer_put_string(&out, text, length); lc_result r = lc_writer_destroy(&out); /* the final flush */ if (lc_is_err(r)) { /* r.error is the errno of the write that failed, such as LC_ERR_NOSPC */ } ``` - Ignoring the result of `lc_writer_flush` or `lc_writer_destroy` gets a `-Wunused-result` warning. - A pointer to a function that returns `void` no longer takes these functions: GCC 14 and clang 16 reject it, and GCC 13 warns. - An object compiled against 0.1.1 still links and works: the `lc_result` comes back in registers, and the object ignores them. - `` gives the whole contract, and [Contracts](contracts.html#writer) the test that holds lightc to it. ### lc_socket_listen_on takes an address {#listen-on} | 0.1.1 | 0.2.0-rc1 | |---|---| | `[[nodiscard]] lc_result lc_socket_listen_on(uint16_t port, int32_t backlog);` | `[[nodiscard]] lc_result lc_socket_listen_on(const lc_socket_address *addr, int32_t backlog);` | A call that passes a port no longer compiles. For what it did, listening on every interface, pass `lc_socket_address_any(port)`; a server can now listen on loopback alone: ```c lc_socket_address any = lc_socket_address_any(8080); lc_result server = lc_socket_listen_on(&any, 128); /* as lc_socket_listen_on(8080, 128) did */ lc_socket_address local = lc_socket_address_create(127, 0, 0, 1, 8080); lc_result private_server = lc_socket_listen_on(&local, 128); ``` ### Deprecated: lc_socket_create and lc_socket_accept {#deprecated} | 0.1.1 | 0.2.0-rc1 | |---|---| | `[[nodiscard]] lc_result lc_socket_create(int32_t type);` | `[[deprecated("use lc_socket_open(LC_AF_INET, type, 0)"), nodiscard]] lc_result lc_socket_create(int32_t type);` | | `[[nodiscard]] lc_result lc_socket_accept(int32_t socket_fd, lc_socket_address *client_addr);` | `[[deprecated("use lc_socket_accept_flags(socket_fd, addr, &addr_size, 0)"), nodiscard]] lc_result lc_socket_accept(int32_t socket_fd, lc_socket_address *client_addr);` | Both still work, and each call warns with its replacement: `lc_socket_open` takes any family and protocol, and `lc_socket_accept_flags` passes accept4's flags. ### lc_version moved to lightc/version.h {#version} | 0.1.1 | 0.2.0-rc1 | |---|---| | `lightc/types.h: [[gnu::const]] static inline int32_t lc_version(void);` | `lightc/version.h: [[gnu::const]] static inline int32_t lc_version(void);` | `` includes the new ``, so code that has `lc_version` and `LC_VERSION_*` from it needs no change. Only the `lc_arena` users of [Struct layouts](#layouts) must be recompiled. - The release candidates of 0.2.0 share the tag with 0.2.0, but their API can still change between them: build everything with each one. A `write(2)` to a pipe still raises it: see [Contracts](contracts.html#sigpipe). - **The loader refuses what it cannot load correctly.** `lc_library_open` now applies PLT and RELR relocations, honours each segment's `p_align` and follows the kernel's page size. A library it used to load half-relocated now fails: with `LC_ERR_UNSUPPORTED` for thread-local storage, IFUNC and symbol versions, with `LC_ERR_RELOC_FAILED` for a relocation it cannot apply, with `LC_ERR_MALFORMED_ELF` for a malformed file, and with the kernel's errno, such as `EACCES`, when the kernel refuses the file. `lc_library_find_symbol` gives an absolute symbol its value, where it added the load bias. - **A plugin must not link `liblightc.a`.** Its copy of lightc would share the host's per-thread block, and `lc_library_open` refuses one that defines `lc_heap_*`, `lc_tls_*` or `lc_abi_*` symbols, with `LC_ERR_UNSUPPORTED`. See [Contracts](contracts.html#plugins). - **Precision 0 rounds ties to even.** `lc_format_add_double_precision` at precision 0 rounds as printf's `%.0f` does: 0.5 prints 0, 2.5 prints 2. With pad `'0'`, `lc_format_add_signed_padded` puts the sign first, `-00042`, and the time formatters print a year before 0 with a minus sign. - **Locks are private to one process.** The mutex, condition variable, read-write lock, barrier and once wait on private futexes, so in `MAP_SHARED` memory a waiter in one process is never woken by another. Use a futex of your own, with the shared flag, there. - **`lc_reader` does not take EAGAIN for the end of the stream.** On a non-blocking fd with no data, a read returns -1 or a short count with the reader's `error` set to `LC_ERR_AGAIN`, and the stream goes on; a read error ends it with `error` set. `lc_reader_read_line` can return part of a line on such a fd, and the next call the rest. - **The io_uring ring loses nothing.** An entry that a failed `io_uring_enter` did not take stays queued and is offered again, `lc_async_peek` moves completions the kernel held back into the queue, and `lc_async_ring_create` fails with `LC_ERR_OPNOTSUPP` on a kernel without `IORING_FEAT_NODROP`. `lio_loop_run` returns on an io_uring error it cannot wait out, which `lio_loop_error` gives, where it spun for ever. - **Sleeps end on time.** `lc_time_sleep_milliseconds` and `lc_time_sleep_microseconds` sleep to a deadline, so signals delay them only by their handlers' run, and a sleep of 0 or less returns at once. - **Threads.** `lc_thread_create_with_stack` fails with `LC_ERR_INVAL` below `LC_THREAD_MIN_STACK_SIZE`, and rounds a stack up to whole pages. A handle whose create failed is all zeros, so joining it returns at once. A thread that reuses an exited thread's id starts with every TLS slot NULL, and the scheduler and lightio take no TLS key of the program's. - **lightio's coroutine stacks have a guard page**, so a handler that overflows its stack dies of SIGSEGV, as other coroutines do. - **The directory iterator.** Closing an `lc_directory` whose open failed closes nothing, and `lc_directory_next` after a close returns false. - **Files.** `lc_file_read_all` reads to the end, so `/proc` and `/sys` files read whole, and `lc_file_get_size` uses statx: a FIFO gives 0 at once instead of blocking. - **Logging.** There is no log lock: a line goes out in one `writev` or `write`, a child can log after fork, and threads behind a blocked write sleep instead of spinning. A JSON line's `ts` is 0 without a clock, and a message cut short never ends inside a UTF-8 sequence. - **`lc_error_name` names every Linux errno**, such as `"EBADF"` for 9, where it returned `"UNKNOWN"`. Check code that tests for `"UNKNOWN"`. - **The arena and the containers check their arguments.** `lc_arena_allocate_aligned` returns NULL for an alignment that is 0 or not a power of two, `lc_arena_create` fails for a size within a page of `SIZE_MAX`, and `lc_array_push` and `lc_array_insert` copy the right value when it points into the array itself. ## Kernel {#kernel} lightc 0.2.0 needs Linux 5.10 or later. [Contracts](contracts.html#kernel) gives what needs which version. ## Building and testing {#build} - **Run `./configure` again.** ninja does not regenerate `build.ninja`, and one written by 0.1.1 has no `regress`, `smoke` or `api-check` target. - **The environment reaches `configure`.** It now adds `CFLAGS` and `LDFLAGS` after its own flags, and reads `STRIP`, `OBJCOPY` and `SYSROOT`. Unset them when they are meant for another project. - **The arch is `CC`'s.** `configure` takes it from `$CC -dumpmachine`, so `CC=aarch64-linux-gnu-gcc ./configure` sets up a cross build, and an `ARCH` that does not match `CC` stops it. - **A suite that skips every test fails `ninja test`.** Without io_uring, as under qemu-user, set `LIGHTC_TEST_ALLOW_SKIP="test_async test_lightio"`. - **`ninja regress` needs a `kernel.pid_max` of at most 32768**, and lld on aarch64. `AGENTS.md` says why. - **C17 needs GCC 14 or clang.** The public headers use C23's `[[attribute]]` syntax, which GCC 13 rejects before C23.
