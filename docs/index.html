No libc, no system linker scripts, no external dependencies — everything from `_start` to `exit` is implemented on raw Linux syscalls. Targets **x86_64** and **aarch64**. ::toc :::div{.facts cols="1 1 1 1"} **4640 B** tiny hello in CI, x86_64, GCC 14 (measured) +++ **2** architectures +++ **0** runtime dependencies +++ **~5 ns** coroutine switch ::: ## Overview {#overview} lightc is the layer a hosted program normally receives from libc and the C runtime, re-implemented as a small, inspectable library. It provides process startup and teardown, memory allocation, threads and synchronization, coroutines, synchronous and asynchronous I/O, and the usual building blocks (strings, formatting, logging, containers, time, sockets) — each as a module under `include/lightc/` or `include/lightio/`. Two invariants hold throughout the API: - **No hidden state.** There is no global `errno` and no implicit allocator. A fallible call returns its status in an `lc_result` or `lc_result_ptr` value (see [the error model](guide.html#errors)); memory comes from an allocator you name. - **The kernel ABI is the only dependency.** Every external effect is a syscall. Only two source files are per-architecture: the startup stub and the syscall trampoline. ## Modules {#modules} Each module is one public header. Linked modules have a reference page; the rest are documented at their headers. :::div{.cards cols="1 1"} ### [Core & conventions](guide.html) `result.h`, `syscall.h`, `types.h`, `lifecycle.h` — the error model, the raw syscall layer, startup and exit, and the fixed-width types, from the compiler's own freestanding `` and ``. +++ ### [Heap](heap.html) `heap.h` — general-purpose allocator: per-thread bucket allocator over slab pages and segments, lock-free cross-thread frees, a large-block cache, 16-byte alignment. +++ ### [Threads](threads.html) `thread.h` — threads over `clone` with guard-paged stacks, and the futex-based synchronization set: spinlock, mutex, condition variable, read/write lock, barrier, once, and thread-local keys. +++ ### [Coroutines](coroutines.html) `coroutine.h` — stackful coroutines and a cooperative round-robin scheduler, with an assembly context switch over the callee-saved registers. +++ ### [Async & lightio](async.html) `async.h`, `lightio/lightio.h` — the `io_uring` submission/completion ring, and an event loop that runs one coroutine per connection. +++ ### Further modules `socket.h`, `io.h`, `format.h`, `print.h`, `log.h`, `time.h`, `library.h`, `signal.h`, and the `lightdata/` containers are documented at their headers; reference pages follow. ::: ## Conventions {#conventions} | Topic | Summary | |---|---| | Error reporting | `lc_result` (`int64_t value`, `int32_t error`) and `lc_result_ptr` (`void *value`, `int32_t error`); `error` is `LC_OK` or an `LC_ERR_*` code. See [Error handling](guide.html#errors). | | Naming | Public symbols are prefixed `lc_` (`lio_` for lightio); raw syscall wrappers are `lc_kernel_*`; compile-time constants are `LC_*`. | | Strings | Lengths are explicit; APIs do not assume NUL termination. | | Allocation | Allocating calls are `[[nodiscard]]` and return `lc_result_ptr`. | | Thread safety | Noted per function. The heap and synchronization primitives are thread-safe; most data-structure handles are not, unless stated. | ## Building {#building} A shell `configure` script selects a build mode and writes `build.ninja`; `ninja` builds. The toolchain requirement is GCC and ninja only. | Mode | Flags | |---|---| | `./configure debug` | `-O0 -g3`, safety checks on | | `./configure release` | `-O2 -DNDEBUG`, stripped (default) | | `./configure tiny` | `-Os`, smallest binary | | `./configure ubsan` | `-O1 -g -fsanitize=undefined -fsanitize-trap=all`, safety checks on | | Target | Builds | |---|---| | `ninja` | the static library and the examples, `test_plugin.so` among them (every program of `examples/` but `bench_startup` and the libc comparisons `*_musl.c`); not the test suites | | `ninja tests` | the test suites, without running them | | `ninja test` | build and run the test suites | | `ninja regress` | run the regress programs of fixed defects, listed in `tests/regress/manifest` | | `ninja smoke` | run the examples that check their own results, and `lightio_test` | | `ninja bench` | run the benchmarks | The output links statically with lightc's own linker script (`lightc.ld`, or `lightc-tiny.ld` in tiny mode), no-PIE, with no interpreter and no dynamic dependencies. The size at the top of this page is a measurement, not a limit: it is that of `build/hello` in CI's `x86_64 gcc 14 tiny` job, built by Ubuntu 24.04's GCC 14.2 and binutils 2.42, and the job reports it as a notice on every run. That GCC turns on `-fcf-protection` by default, which adds `endbr64` instructions to the code, so a GCC 14 without that default, such as upstream GCC, builds a smaller hello. Another compiler, binutils or change to the sources also gives another size. `configure` builds for the target of `CC` (default `gcc`): the arch is the first field of `$CC -dumpmachine`, x86_64 or aarch64. `AR`, `STRIP` and `OBJCOPY` default to the tools with `CC`'s prefix, or to the plain names when those are not installed, so `CC=aarch64-linux-gnu-gcc` alone sets up a cross build. `CFLAGS` and `LDFLAGS` are added after configure's own flags, and `SYSROOT` is passed as `--sysroot`. `ARCH` is still read for older callers, but it must equal the compiler's arch, or `configure` stops. A cross build can build the test suites without running them with `ninja tests`: ```sh CC=aarch64-linux-gnu-gcc ./configure release ninja all tests ``` In ubsan mode each undefined behavior check is a trap instruction, so no sanitizer runtime is linked: a program that hits one stops with SIGILL on x86_64 or SIGTRAP on aarch64. The binaries are not stripped, so `addr2line` maps the `ip` or `pc` that the kernel logs for it to the check's source line. ubsan links with `lightc.ld`, and the installed `lightc.pc` is the same in every mode. ## Example {#example} A program defines `main` and links against the runtime, which supplies `_start`. No system headers are included. ```c [hello.c]{#hello} #include int main(int argc, char **argv, char **envp) { (void)argc; (void)argv; (void)envp; const char msg[] = "hello from lightc — no libc, no problem\n"; lc_kernel_write_bytes(STDOUT, msg, sizeof(msg) - 1); return 0; } ``` ```sh gcc -ffreestanding -fno-stack-protector -nostdlib -nostartfiles -Iinclude \ hello.c build/liblightc.a -T lightc.ld -static -no-pie -o hello ``` `ninja install` puts the library, the headers, `lightc.pc` and both linker scripts (in `lib/lightc/`) under `/usr/local`, below `$DESTDIR` if set. pkg-config then gives the same flags, with `-mno-outline-atomics` added on aarch64: ```sh gcc $(pkg-config --cflags lightc) hello.c $(pkg-config --libs lightc) -o hello ``` The `--libs` flags already pass `-T` with `lightc.ld`. A second `-T` is added to the first, not used in its place, so to link with `lightc-tiny.ld` swap its path in. `pkg-config --variable=ldscript_tiny lightc` prints that path: ```sh gcc $(pkg-config --cflags lightc) hello.c \ $(pkg-config --libs lightc | sed "s|-T[^ ]*lightc\.ld|-T$(pkg-config --variable=ldscript_tiny lightc)|") -o hello ``` See [Core & conventions](guide.html) for the startup sequence, the error model and the syscall layer.
