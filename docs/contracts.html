Two things are not fork-safe: - **The heap.** A fork while another thread holds one of the heap's locks leaves the child stuck at its first allocation that takes it, and a child keeps the parent's per-thread heap identity. Until a later release makes the heap fork-safe, the child of a process with more than one thread calls only the clone-safe functions of `api/index.md` until it execs or exits, and a child that goes on without exec creates no thread. - **Locks.** The mutex, condition variable, read-write lock, barrier and once of `` are private to one process: in `MAP_SHARED` memory that two processes share, a waiter in one is never woken by the other. A child's copy of a lock is a lock of its own, in the state the fork found it. The child of a raw `clone` system call, which has no lightc thread of its own, may call only the clone-safe functions of `api/index.md`, as [`test_index`](#handlers) checks. ### Exit {#exit} | Default | Enforced by | |---|---| | Returning from `main` calls `exit_group` with its value, which ends every thread of the process. Its return value is its exit status, which nothing collects: hand a result back through the thread's argument. ## Async I/O {#rings} - **A ring belongs to one thread at a time.** The `lc_async_*` calls take no lock, so threads that share a ring do so under a lock of their own, as `examples/httpd.c` does. - **A lightio loop belongs to the thread that runs it.** `lio_loop_run_threaded` gives each worker a ring and a coroutine pool of its own. `lio_read`, `lio_write` and `lio_sleep` are called only from a handler's coroutine. - **An entry stays queued until the kernel takes it.** An `io_uring_enter` that fails with `EAGAIN` or `EBUSY` leaves its entries for the next flush or wait, and `lc_async_flush_ex` and `lc_async_wait_ex` report its errno. On 5.10 and later only `fchmodat2` and `mount_setattr` can be missing from the kernel itself, so there the probes mostly find what a seccomp filter or a sysctl takes away. ### fchmodat2 and the O_PATH fallback {#fchmodat2} `lc_kernel_fchmodat` with flags 0 is `fchmodat`, which follows a symlink. The kernel's `fchmodat` takes no flags, so with flags such as `AT_SYMLINK_NOFOLLOW` the call is `fchmodat2`, from Linux 6.6. Without it, the call returns `-EOPNOTSUPP` for every file, and never drops the flags to change the mode of a symlink's target. Before 6.6 no system call changes the mode at a path without following a symlink there. `fchmodat` takes no flags, so no `AT_EMPTY_PATH` either. `fchmod` needs a descriptor opened to read or write: it fails with `EBADF` on an `O_PATH` one, and such an open needs permission to read or write the file and wakes a FIFO or a device. Where `lc_probe_kernel(LC_KFEAT_FCHMODAT2)` fails, a caller can do what glibc does, as `test_fchmodat_without_fchmodat2` does under a filter: 1. Open `path` with `O_PATH | O_NOFOLLOW | O_CLOEXEC`. The descriptor holds the file without opening it, so it reads nothing and wakes no FIFO or device, and for a symlink it holds the symlink, not its target. `` does not define `O_PATH`: it is `010000000` on both arches. 2. `fstat` the descriptor, or `statx` it with `AT_EMPTY_PATH` (`0x1000`), and stop with `EOPNOTSUPP` if it is a symlink. 3. Otherwise call `lc_kernel_fchmodat(AT_FDCWD, "/proc/self/fd/", mode, 0)`, which follows the `/proc` link to the file the descriptor holds: the one step 2 looked at, even if `path` has been renamed or replaced since. It needs `/proc` mounted, and fails with `ENOENT` without it. 4. Close the descriptor. A symlink has no fallback, as it has no mode to change: Linux checks no symlink's mode bits. From 6.6 the kernel refuses to change them, with `EOPNOTSUPP`. Before 6.6 a chmod through `/proc` of a symlink's descriptor does what the filesystem does, and some change the bits and then fail with `EOPNOTSUPP`. So step 2 refuses a symlink, as `lc_kernel_fchmodat` with `AT_SYMLINK_NOFOLLOW` does on every kernel. {.source} The headers say the rest: `` for the writer and reader, `` for logging, `` for threads and locks, `` for the loader, `` and `` for the ring and the loop. `AGENTS.md`, at the root of the source tree, is the guide for changing lightc itself.
